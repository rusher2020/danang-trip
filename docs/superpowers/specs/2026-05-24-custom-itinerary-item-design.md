# 커스텀 일정 항목 추가 기능 설계 (Custom Itinerary Item)

> 작성 2026-05-24. **이 세션은 설계, 구현은 별도 세션**(executing-plans).

## 배경·문제

지금까지 일정(타임라인·시간표·지도)은 `index.html`의 `ITINERARIES` + `PLACES` 데이터에 **하드코딩**으로만 추가 가능. 런타임 추가는 "📝 내 일정"이 **후보카드를 담는** 것뿐. → **후보카드에 없는 장소/일정**(예: "공항 미팅", "객실 낮잠 1.5h", 즉석에서 찾은 식당)은 코드 편집 없이는 못 넣음. 레퍼런스(first6)에도 없는 기능.

## 목표

"📝 내 일정" 뷰에서 **카드에 없는 커스텀 항목을 화면에서 직접 추가**. 위치를 넣으면 기존 항목처럼 **지도 핀 + 클릭→지도 연동**, 안 넣으면 타임라인/시간표 전용. native 팝업 0(기존 인라인 UX 일관).

## 사용자 흐름

1. 내 일정 뷰의 `＋ 직접 추가` 버튼 → 화면 내 인라인 시트.
2. 폼 입력:
   - **제목**(필수), **날짜**(필수, `TRIP_DAYS` 칩), **시각**(필수/미정 — 기존 시각 피커 재사용)
   - **위치**(선택): 이름 **검색(지오코딩)** → 결과 선택 → **미니 지도 핀 미세조정**
   - **아이콘/카테고리**(선택, 기존 카테고리 아이콘 셋), **이동수단·비용 메모**(선택, 예 "그랩카 · 5만동")
3. 담기 → 시간순 자동 정렬, "내가 추가" 뱃지.
4. 타임라인 인라인 칩 에디터로 시간변경/날짜이동/삭제 + 커스텀은 제목·위치·비용도 편집.

## 데이터 모델

- `myPlan` 항목 확장: 후보카드는 카드 id 참조였으나, 커스텀은 카드가 없으므로 **인라인 저장**:
  ```js
  { custom:true, day, time, title, coords:[lat,lon]|null,
    icon, cat, mode, cost, memo }
  ```
- `myPlanToItinerary()`가 커스텀 항목도 ITINERARY 형태로 변환: `coords` 있으면 임시 place처럼(지도 핀+클릭 포커스), 없으면 place 없는 항목(타임라인/시간표만). 기존 재렌더 관용구(`ITINERARY=myPlanToItinerary(); applyDayColors(ITINERARY); renderAll();`) 유지.
- 영속성: 기존 localStorage `danang-myplan` + URL 해시 `mp=`에 커스텀 필드 직렬화 포함. **해시 길이 주의**(좌표·텍스트 추가 → 공유링크 길어짐, 인코딩 압축 고려).

## 이동수단·비용·경로 (핵심) — "계획 시점 계산, 현지 오프라인 재생"

**설계 원칙**: 계획은 출국 전(온라인)에 완성, 현지선 보기만 → 모든 외부 호출은 **추가/편집 시점에 1회**만 하고 결과를 **영속 저장**, 뷰 시점엔 저장본만 읽음 (프리셋 `ROUTES_CACHE` 모델과 동일 → **현지 인터넷 불필요**).

- **위치(지오코딩)**: 이름 검색 결과 좌표를 **항목에 저장**(`coords`). 이후 재호출 없음.
- **소요시간·도로경로**: 추가/편집 시(온라인) 해당 좌표쌍에 OSRM **1회 호출** → 경로 폴리라인+시간을 **localStorage 경로 캐시**(좌표쌍 키, 기존 `ROUTES_CACHE` 미러)에 저장. 뷰·현지에선 캐시에서 읽어 "🚐 X분"+도로선 렌더.
- **비용·이동수단**: 자동 불가(원래 사람 추정치) → 폼 **선택 입력**, 항목에 저장, 비우면 미표시.
- **폴백**: 캐시에 없는 좌표쌍을 오프라인에서 만나면(예: 현지에서 순서 변경) → 직선거리 기반 대략 시간 + 직선 점선. 지오코딩 안 되면 지도 탭으로 위치 지정.

## 컴포넌트 재사용

- 인라인 시트: `openQuickAddSheet`/`buildPickerMarkup`/`bindPicker` 패턴(백드롭·✕·Esc, `aria-labelledby`).
- `myPlanToItinerary`, `applyDayColors`+`renderAll`, `TRIP_DAYS`, 카테고리 아이콘 셋, 기존 인라인 칩 에디터(`mpEditing`/`mpControlsHtml`).
- 지도: 기존 Leaflet 인스턴스 재사용(미니 지도는 별 인스턴스 또는 메인 맵 임시 모드).

## 외부 의존·리스크

- 지오코딩(Nominatim)·OSRM 호출은 **계획 시점(출국 전, 온라인)에만** 발생 → **현지 뷰는 인터넷 불필요**(저장된 좌표·경로 캐시 재생). 지도 타일·카드 사진의 기존 온라인 의존은 별개·기존 이슈.
- Nominatim 사용정책(rate limit, User-Agent) 준수. 베트남 검색 정확도 편차 → 지도 미세조정으로 보정.
- `mp=` 해시엔 항목 데이터(좌표 포함)만, **경로 폴리라인 캐시는 localStorage에만**(해시 비대화 방지). 공유링크 수신자는 온라인이면 경로 재생성, 오프라인이면 직선 폴백.

## 범위 밖

- 프리셋 `ITINERARIES`(A~E)·하드코딩 `TRAVEL_*`/`ROUTES_CACHE`는 불변(커스텀은 myPlan에만).
- 커스텀 항목을 후보카드 풀에 영구 등록하는 것(별도).

## 검증 (필수)

1. 헤드리스(데스크톱+모바일): 추가/정렬/편집/삭제/새로고침·공유링크 복원, JS 에러 0, native 팝업 0.
2. 위치 있는 커스텀 → 지도 핀+클릭 포커스 동작, OSRM 시간/경로 표시; 위치 없는 커스텀 → 타임라인/시간표만.
3. **계획→현지 시뮬레이션**: 온라인에서 커스텀 추가(좌표·경로 캐시 저장) → 네트워크 차단(오프라인)으로 새로고침 → 저장된 좌표·도로경로·시간이 정상 렌더되는지 확인. 캐시 미스 좌표쌍은 직선 폴백.
4. 프리셋 불변(깊은 복사) 재확인, 해시 라운드트립 보존.
