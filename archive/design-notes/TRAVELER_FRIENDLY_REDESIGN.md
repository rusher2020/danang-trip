# 여행자 친화형 재설계안

작성일: 2026-05-09
대상: 다낭 가족여행 플랜북 1차 구현 이후 2차 디자인 재작업

## 1. 핵심 판단

현재 화면은 여행자에게 필요한 정보를 담고 있지만, 표현 방식이 여행자 친화적이지 않다. `판단 기준`, `후보`, `대안`, `진행 여부` 같은 단어는 여행 앱보다 기획 문서, 리스크 보드, 운영 대시보드에 가깝다.

이 앱의 본질은 다음이어야 한다.

```text
여행 전에는 빠뜨릴 것을 줄여주고,
여행 중에는 지금 갈 곳과 쉬운 선택지를 바로 보여주는 가족 여행 동행 앱.
```

따라서 2차 수정은 단순 색 변경이 아니라 **정보 구조와 언어의 관점 전환**이다.

## 2. 사용자 상황

### 여행 전

사용자가 원하는 것:

- 빠뜨린 준비물이 있는지
- 항공/호텔/수하물/조식 확인이 끝났는지
- 아이와 함께 가도 무리 없는 일정인지
- 꼭 예약하거나 미리 확인할 것이 무엇인지
- 가볼 곳을 너무 많이 비교하지 않고 적당히 추리고 싶은 것

사용자가 원하지 않는 것:

- 후보 평가표
- 판단 기준 목록
- 진행/중단 조건표
- 너무 많은 장소 카드
- 조사 문서처럼 긴 설명

### 여행 중

사용자가 원하는 것:

- 오늘 일정
- 지금 갈만한 곳
- 더우면 어디로 바꿀지
- 아이들이 피곤하면 쉬운 일정이 무엇인지
- 지도 바로 열기
- 식사/화장실/실내/숙소 복귀 같은 현실적 선택
- 다음 이동 전에 확인할 것

사용자가 원하지 않는 것:

- 바나힐 진행 여부를 회의처럼 판단하는 화면
- 대안이라는 실패 느낌
- 후보라는 불확정 느낌
- 긴 후기 분석
- 출처 문서가 주 액션처럼 보이는 화면

## 3. 화면의 언어를 전면 교체

아래 용어는 화면에서 쓰지 않는다.

```text
판단 기준
후보
후보 카드
대안
진행 여부
진행
중단
의사결정
Decision Board
Expert Summary
Scenarios
```

대신 아래 용어를 쓴다.

```text
오늘
이번 여행
가볼 곳
꼭 가볼 곳
쉬운 일정
가볍게 보내기
더운 날엔
비 오면
아이들이 피곤하면
여행 팁
숙소 이동
출발 전에
현지에서
지도
준비 체크
```

용어 교체표:

| 현재 | 변경 |
| --- | --- |
| 판단 기준 | 여행 팁 |
| 후보 카드 | 가볼 곳 |
| 우선 후보 | 꼭 가볼 곳 |
| 대안 | 쉬운 일정 |
| 컨디션 대안 | 가볍게 보내기 |
| 다음 결정 | 다음에 정할 일 |
| 바나힐 진행 여부 | 바나힐은 전날 정하기 |
| 진행 | 가기 좋은 날 |
| 중단 | 쉬는 게 나은 날 |
| 대안 보기 | 쉬운 일정 보기 |
| 후보 보기 | 가볼 곳 보기 |
| 장소 | 가볼 곳 |
| Fixed Flow | 숙소 이동 |
| Daily Plan | 일정 |
| Need Input | 출발 전 확인 |

## 4. 새 앱 구조

하단 내비게이션은 4개를 유지한다.

```text
오늘 / 일정 / 가볼 곳 / 준비
```

만약 `가볼 곳`이 하단 내비에서 너무 길면 하단은 `장소`를 유지해도 된다. 단, 화면 내부 제목은 반드시 `가볼 곳`이어야 한다.

### 오늘

여행 전과 여행 중 모두 가장 먼저 보는 화면.

여행 전에는:

```text
출발 전에 이것만
가볍게 보내기
가볼 곳 미리보기
다음에 정할 일
숙소 이동
```

여행 중에는:

```text
오늘 일정
지금 가기 좋은 곳
더우면 이렇게
다음 이동
숙소로 돌아가기
```

### 일정

날짜별 전체 흐름을 보는 화면.

이 화면도 `recommended`, `flexible`, `candidate` 같은 원본 상태를 그대로 보여주면 안 된다. 사용자가 이해할 수 있는 말로 바꾼다.

```text
확정
좋은 흐름
가볍게 조정
쉬운 일정
```

### 가볼 곳

기존 `후보 카드`를 완전히 대체한다.

필터:

```text
전체 / 꼭 가볼 곳 / 쉬운 일정 / 놀거리 / 식사 / 쇼핑 / 실내
```

장소 카드의 핵심 질문:

```text
왜 가면 좋은가?
언제 가면 좋은가?
아이들과 괜찮은가?
더우면 힘든가?
지도는 어디인가?
```

### 준비

여행 전 준비와 현지에서 필요한 메모.

상단:

```text
출발 전 확인
남은 확인 15개
```

그 아래:

```text
항공·수하물
호텔·조식
아이 음식·건강
쇼핑
긴급/현지 메모
가족 메모
```

## 5. 모바일 첫 화면 상세 설계

### 여행 전 상태

현재 날짜가 여행 전이면 첫 화면은 이렇게 시작한다.

```text

7.24-7.29 · 성인 2 · 아이 2

┌──────────────────────────────┐

│ 먼저 확인하면 됩니다.         │
│                              │
│ 남은 확인 15개                │
│ [준비 체크]                   │
└──────────────────────────────┘
```

### 여행 중 상태

여행 기간 중이면 첫 화면은 이렇게 바뀐다.

```text

오전
오행산은 컨디션 좋을 때만 짧게
[지도] [건너뛰기]

낮
하얏트 수영장과 낮잠
[숙소 보기]

저녁
아이들이 괜찮으면 용다리
[지도] [쉬운 일정]
```

## 6. 카드 설계

### 출발 전에 이것만

목표:

- 첫 화면에서 가장 사용자 친화적인 카드
- 준비 스트레스를 줄여주는 카드

카피:

```text
출발 전에 이것만
항공편·수하물·조식 조건을 먼저 확인하면 됩니다.
바나힐과 외부 일정은 전날 컨디션을 보고 정해도 괜찮아요.
```

CTA:

```text
준비 체크
```

### 가볍게 보내기

목표:

- `대안`이라는 실패감을 없앤다.
- 가족 여행에서 쉬는 일정도 좋은 일정이라는 느낌을 준다.

카피:

```text
가볍게 보내기
더위·비·피곤한 날엔 리조트 안에서 쉬어도 좋아요.
하얏트 수영장과 Camp Hyatt를 먼저 봐두세요.
```

CTA:

```text
쉬운 일정 보기
```

### 가볼 곳

목표:

- `후보 카드`가 아니라 여행자가 기대감을 갖고 둘러보는 장소 목록.

카피:

```text
가볼 곳
아이들과 가기 좋은 곳만 추려뒀어요.
호이안, 하얏트, 바나힐, 시내 쇼핑을 편하게 볼 수 있습니다.
```

CTA:

```text
가볼 곳 보기
```

### 다음에 정할 일

목표:

- 바나힐 정보는 유지하되 첫 화면을 지배하지 않게 한다.

카피:

```text
다음에 정할 일
바나힐은 7/26 밤에 날씨와 아이 컨디션을 보고 정하세요.
```

상세 안에서만 보여줄 항목:

```text
가기 좋은 날
쉬는 게 나은 날
이렇게 바꾸기
```

## 7. 색감 방향

현재의 베이지+청록+주황 조합은 관리 문서 느낌이 강하다. 밝은 휴양지 톤으로 바꾼다.

권장 토큰:

```css
:root {
  --bg: #fafaf7;
  --surface: #ffffff;
  --surface-soft: #f3f8f7;
  --ink: #1f2428;
  --muted: #667085;
  --line: #e8e3da;
  --primary: #147c86;
  --primary-strong: #0b555d;
  --primary-soft: #e7f4f3;
  --warm: #e08a3e;
  --warm-soft: #fff3e6;
  --green-soft: #eef7f0;
  --blue-soft: #edf7fb;
  --shadow-soft: 0 10px 28px rgba(31, 36, 40, 0.07);
}
```

적용:

- 첫 카드는 주황 배경/테두리 금지.
- 첫 카드는 흰색 또는 `primary-soft` 배경.
- 주황은 `더운 날엔`, `주의`, `날씨` 같은 작은 포인트에만 사용.
- 주요 버튼은 `primary`.
- 보조 버튼은 outline보다 조용한 텍스트 버튼.

## 8. 메인 세션 작업 지시

```text
TRAVELER_FRIENDLY_REDESIGN.md 기준으로 2차 디자인 수정을 진행해줘.

핵심은 "판단/후보/대안" 중심 화면을 "오늘/가볼 곳/쉬운 일정/준비" 중심의 여행자 친화 앱으로 바꾸는 것입니다.

반드시 제거할 화면 용어:
- 판단 기준
- 후보
- 후보 카드
- 대안
- 진행 여부
- 진행/중단
- 의사결정

대체 용어:
- 여행 팁
- 가볼 곳
- 꼭 가볼 곳
- 쉬운 일정
- 가볍게 보내기
- 다음에 정할 일
- 가기 좋은 날
- 쉬는 게 나은 날

모바일 첫 화면 순서:
1. 여행명
2. 출발 전에 이것만
3. 가볍게 보내기
4. 가볼 곳
5. 다음에 정할 일

구체 작업:
1. `오늘` 탭에서 바나힐 결정표를 첫 카드에서 내리고 `다음에 정할 일` 카드로 낮춰줘.
2. 첫 카드는 `출발 전에 이것만`으로 만들고 준비 체크 CTA를 둬.
3. `컨디션 대안` 또는 `대안` 영역은 `가볍게 보내기`와 `쉬운 일정`으로 바꿔줘.
4. `후보 카드`와 장소 탭 내부 제목은 `가볼 곳`으로 바꿔줘.
5. 필터 라벨도 여행 앱 언어로 바꿔줘. 예: `우선 후보` -> `꼭 가볼 곳`, `액티비티` -> `놀거리`, `맛집` -> `식사`.
6. 첫 카드의 주황 테두리/배경을 없애고 밝은 흰색 또는 soft teal 계열로 바꿔줘.
7. 한 카드에 primary filled 버튼은 하나만 둬.
8. WebKit 390x844에서 첫 화면이 관리 보드가 아니라 여행 앱처럼 보여야 해.

검수 기준:
- 첫 화면에서 "내가 지금 뭘 하면 되는지"가 바로 보여야 한다.
- `후보`, `대안`, `판단 기준`이라는 단어가 화면에 보이면 실패다.
- 바나힐 관련 정보가 첫 화면을 지배하면 실패다.
- 가볼 곳 화면은 후보 평가표가 아니라 여행 장소 탐색처럼 보여야 한다.
```
